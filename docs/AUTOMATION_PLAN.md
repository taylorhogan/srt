## Context

The observatory already runs a planned night with no human touch (noon decision → roof → up to 3 slots → park → close → flats; first conductor-planned night 2026-10-17). What still needs a person, in the owner's words plus what the inventory added:

| Gap | Today |

**Owner decisions (2026-10-29):** publishing is **one-tap approval** with auto-publish after N days; alerting is **owner only, escalating** (p2 until acked, daily noon reminder while blocked); queue filling is **suggest, owner approves**; order is **A stop + B alerting → C filters → D publishing → E suggestions → F rest**; **disk space on both machines is a stopping item**.

Every phase ships beside the legacy path, shadows first where a decision changes behaviour (ADR 0005), has pytest with fakes (conductor stubbed by `tests/conftest.py`), and names a clean-night criterion. Owner-visible decisions are logged in ARCHITECTURE_PLAN.md and an ADR where a rule changes.

### Three implementation decisions proposed here (owner may override)

1. **Article prose on the Spark via an Anthropic API key** in `config_private.py` (`cfg["anthropic"]["api_key"]`), with a facts-only fallback article when the key is absent or fails. A Claude Code session is free but is an interactive tool an heir may not have (ADR 0011 "heir-operable"); a key is one line in SUCCESSION.md and the pipeline degrades instead of blocking.
2. **Approval by reply command** (`approve <dso>` / `reject <dso> [why]`), not a button: the chat has no action cards, and `publish` is already taken (it renders a sweep variant, `super_user_commands.publish_cmd`).
3. **Spark → PC via the existing ssh** (`morning_trigger._ps`) for both the conductor events (`RENDER_DONE`, `PUBLISH_DONE`) and the subscriber announce (`site_push.py --yes` on the PC, which holds the host key). The conductor allowlist stays loopback-only and the host key stays on one machine.
